# API documentation status

Controller and DTO contracts were inspected in source. The runtime OpenAPI export and successful request/response pairs below were captured from a separate Compose project with its own volume and loopback ports; the existing project was left running and untouched.

The exported OpenAPI file contains 10 paths and 16 operations, including one JSON-producing UI helper route. The inventory below records REST/JSON routes; HTML form and view routes are listed separately because they return pages or redirects, not JSON contracts. TC-11 remains a separate observed 403 and is not substituted for the successful status-update example.

## Route inventory to verify

The inventory is based on controller mappings. Authentication is session-based (`currentUser`), not a bearer-token contract.

Captured examples come from an isolated fresh database and contain generated BT3 fixture tickets. Sample phone numbers, technician names and serial numbers are redacted in saved exchanges; replace redacted fields with fixture values before replaying. `openapi.json` is the runtime response from `/v3/api-docs` (HTTP 200). The expected error mappings above were checked against `GlobalExceptionHandler`; each row's linked example records the observed success status and response.

## HTML/view routes reviewed

These routes were found in the controllers and are not REST JSON contracts: `GET /`, `GET /tickets/{id}`, `GET /login`, `POST /login`, `GET /logout`, `GET /tickets/unassigned`, `GET /tickets/{id}/assign`, `POST /tickets/{id}/assign`, `GET /appointments/new`, `POST /appointments`, `GET /lookup`, `POST /lookup/confirm/{appointmentId}`, `GET /technician/my-tickets`, and `POST /technician/tickets/{id}/status`. They render Thymeleaf pages or redirect. Their UI behavior is represented by test cases where evidence exists; this API appendix does not claim a captured HTTP example for each HTML route.

The application also has HTML form routes. They are not REST JSON contracts and are not covered as API examples here. Exact error status mappings must be confirmed against `GlobalExceptionHandler` and live responses before publishing an endpoint-level error matrix.
